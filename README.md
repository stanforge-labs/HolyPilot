# HolyPilot

**HolyPilot** — веб-платформа для работы с рекламными кабинетами и маркетинговыми данными через AI. Пользователь подключает свои аккаунты, выбирает доступные рекламные кабинеты, смотрит диагностику и отчёты, а затем работает с ними в совместимом MCP-клиенте. Изменения рекламы проходят через отдельный preview и подтверждение владельца.

Проект вырос из отдельного MCP-сервера: в репозитории есть личный кабинет, API, авторизация, интеграции с провайдерами, фоновые задачи, отчёты и инструменты для AI-клиентов. **MCP** здесь означает протокол подключения, а не название продукта.

## Возможности

| Область | Что реализовано |
|---|---|
| Личный кабинет | Регистрация и вход, рабочие пространства, подключения, выбор аккаунтов, диагностика и профиль |
| Рекламные платформы | OAuth и чтение данных Meta Ads и Google Ads; поддерживаемые возможности других провайдеров зависят от окружения и выданных доступов |
| AI-подключение | Частный MCP endpoint, OAuth для совместимых клиентов и инструменты чтения данных |
| Контролируемые изменения | Проверка прав и объекта, preview, отдельное подтверждение в браузере, журнал действий и контроль результата; доступность WRITE задаётся флагами конкретного окружения |
| Маркетинговые инструменты | Отчёты, данные Google Search Console и AI-аудит сайта |
| Администрирование | Управление доступом к рабочим пространствам и служебная диагностика |

Наличие функции в коде **не означает**, что она включена для каждого аккаунта или в production. В частности, Google Ads WRITE ограничен отдельными профилями и защитными проверками. Текущий статус конкретного окружения следует проверять отдельно от состояния репозитория.

## Как работает HolyPilot

1. Владелец входит в личный кабинет и выбирает своё рабочее пространство.
2. Подключает рекламную платформу через OAuth и выбирает разрешённые аккаунты.
3. Подключает Codex, Claude, ChatGPT или другой совместимый клиент через частный MCP endpoint.
4. Получает ответы и отчёты по доступным ему данным.
5. Если операция предполагает изменение, сначала видит план и результат проверки. Применение требует отдельного подтверждения и проходит через дополнительные ограничения.

Пароли, OAuth-токены и ключи провайдеров не должны попадать в Git, отчёты или публичные логи.

## Локальная разработка

Требуются Node.js 24, pnpm 11.1.3 и Docker с Compose. Для v2:

```powershell
Copy-Item .env.v2.example .env.v2
pnpm install --frozen-lockfile
pnpm dev
```

Перед первым запуском настройте только локальные значения в `.env.v2`; реальные секреты не коммитятся. Подробности, адреса сервисов и вариант запуска через Docker: [V2 local development](docs/architecture/v2/LOCAL_DEVELOPMENT_RU.md).

Основные проверки:

```powershell
pnpm lint
pnpm typecheck
pnpm test
```

Серверные миграции, OAuth-настройки и production-развёртывание выполняются по отдельным инструкциям и не входят в обычный запуск разработки.
